# Peepland — Техническое задание v2.0

**Единственный источник технической истины.**  
Продуктовый дизайн — [GDD.md](GDD.md) (GDD 2.0). При конфликте кода со старым ТЗ v0.6 / инди-выживачем / P2P — побеждает этот документ.

**Платформа:** UGC Peepland для Telegram Mini Apps (TMA).  
**Не делаем:** инди-выживач на двоих, Робинзонов, WebRTC/P2P, закатные кинематографические шейдеры.

ТЗ v0.6 удалено. Любой код P2P / WebRTC / sunset-атмосферы подлежит безжалостному удалению при следующем рефакторинге.

---

## 1. Инфраструктура и сеть (смерть P2P)

### 1.1 Отказ от WebRTC

- Убираем P2P. Платформа требует масштабирования.
- Классический **клиент–сервер** через **WebSockets**.

### 1.2 Эфемерные RAM-комнаты

- Игровая сессия живёт **только в оперативной памяти** сервера (Node.js / Bun).
- **Запрещено** писать каждый поставленный блок в PostgreSQL/SQLite во время матча.
- Диск (БД) — только для готовых статичных **Чертежей (Blueprints)** карт.
- Пустая комната → удаляется из RAM. Чертеж остаётся для следующего запуска.

### 1.3 Сетевой tick rate

- Строгие **20 тиков/с (50 ms)** на сервере.
- Клиент **отвязан от FPS**: не спамит пакетами из `requestAnimationFrame`.

### 1.4 Интерполяция

- Клиенты сглаживают чужих игроков (**Lerp / Slerp**) между сетевыми тиками.

## 2. Интеграция с Telegram (идентификация и экономика)

### 2.1 Авторизация

- **Не** `localStorage` как главный источник правды об идентичности.
- Идентичность: `window.Telegram.WebApp.initDataUnsafe.user.id` (мгновенно, бесшовно).
- Верификация `initData` на сервере — для доверенных операций (оплата, сохранение чертежа).

### 2.2 Монетизация

- Архитектурная база под оплату **Telegram Stars** для внутрисессионных микротранзакций.
- Покупка уникальных блоков / пушек / бустов **прямо в матче**.
- Выручка 50/50 платформа ↔ автор Чертежа (см. GDD §7).

## 3. Рендер и графика (Clean & Crisp)

### 3.1 Освещение

- Жёсткий **«Ублюдский День» (Midday)**.
- Солнце высоко: elevation **~50–80°**.
- Туман и `clearColor` / фон сцены — **один цвет** (шов горизонта скрыт).

### 3.2 Текстуры

- Генеративный микро-пиксель **8×8**.
- Строго **`NearestFilter`**, без mipmaps / мыла.
- UV — математически точные (`tile/cols` … `(tile+1)/cols`), **без inset 0.001**.
- Анти-тайлинг: **4 вариации** для травы / земли.

### 3.3 Voxel Ambient Occlusion

- Фейковое затенение углов через **`vertexColors`** при сборке геометрии чанка.
- Face culling соседних solid-ячеек сохраняется.

### 3.4 Z-fighting

- Жёсткая блокировка на уровне массива вокселей: **запрет двух блоков в одной координате** (solid → occupied = no-op).

---

## 4. Управление и камера

### 4.1 Mobile-first (TMA)

- Экранные джойстики и тач-зоны **не перекрывают центр** прицела.

### 4.2 Десктоп

- Нативный синхронный **`requestPointerLock()`** для мыши.

### 4.3 Первое лицо

- Присутствие рук + анимация ходьбы (**View Bobbing**).
- Камера от **третьего лица запрещена** (кроме катсцен).

## 5. Инварианты рефакторинга (чеклист удаления)

При следующем сетевом/арт-рефакторинге удалить или заменить:

| Удалить / запретить | Заменить на |
|---|---|
| `P2PRoom`, WebRTC data channels, signaling-as-game-bus | WebSocket rooms, server tick 20 Hz |
| Persist каждого блока в БД во время сессии | RAM voxel grid; БД = Blueprints only |
| `localStorage` как source of truth для user id | Telegram `initData` / `user.id` |
| Sunset / cinematic sky hacks, UV inset | Midday Sky, exact atlas UV |
| Третье лицо в геймплее | FPS + hands + bobbing |
